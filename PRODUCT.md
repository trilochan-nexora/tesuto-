# Product

## Register

product

## Users

Internal engineering, product, design, and quality teams working in the context of a running web application. They need to report a defect at the point where they encounter it, preserve enough visual and technical context for someone else to reproduce it, and triage the resulting work without turning reporting into a separate administrative task.

## Product Purpose

Tesuto shortens the path from noticing a UI problem to assigning, discussing, and resolving it. It combines an embedded point-at-the-interface reporting widget with project inboxes, kanban workflows, comments, analytics, and selective external integrations. Success means reports arrive with useful context, triage is quick, ownership is unambiguous, and teams trust the tracker enough to use it consistently.

## Brand Personality

Approachable, considered, reliable. Tesuto should feel easy to learn without feeling simplistic, visually polished without becoming decorative, and dependable when users are capturing or coordinating important work.

## Anti-references

Avoid Jira-like density, configuration-heavy enterprise workflows, dashboard clutter, and decorative polish that slows routine triage. Avoid novelty controls, ambiguous status language, and metrics that feel like employee surveillance rather than tools for improving delivery.

## Design Principles

1. Keep users in the context of the problem they are reporting.
2. Make the next action obvious and routine actions fast.
3. Reveal complexity progressively instead of exposing every option at once.
4. Preserve evidence and system feedback so users can trust what happened.
5. Use familiar interaction patterns consistently across the widget and dashboard.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Support complete keyboard operation, visible focus, semantic controls, sufficient contrast, reduced motion, touch-friendly targets, text zoom, and status communication that does not depend on color alone.
